# Allora II — standing orders

Allora II is a slow, vast idle fantasy life simulation set in the world of Allora I. The full design is in `docs/design-bible.md`. The current phase plan is the newest `docs/phase-N.md`. Read both before starting work.

## Canon (read first, obey always)

**Canon is the base, not the limit.** Allora II grows Allora's world: new groups, places, people and stories are welcome. But everything grows from canon, carries its land's flavour, and never contradicts it.

Canon sources, in order of authority:
1. `canon/allora-1.html`: the built Allora I game. Its places, people, groups, faiths, schools, items, ranks and text.
2. `canon/polygoetia.md`: the Polygoetia reference (the fifth land).
3. `canon/magic_design.md`: the magic design notes (if present).
4. `docs/design-bible.md`: for systems, and anything the first three do not cover.

Rules:
- **Never edit anything in `canon/`.**
- `content/canon/` is generated by the extractors. Change it only by re-running them, or in a PR labelled `canon-change` that says why.
- Every new entry in `content/` has `origin: allora2` and a `roots` list naming the canon ids it grows from.
- New names follow the culture guide for their land (`docs/lore/cultures/`). Never reuse or near-copy a canon name.
- No canon person dies, changes allegiance or changes role; no canon place moves; no new history overwrites an old one.
- If two canon sources disagree, the higher one wins. Log the clash in `docs/lore/conflicts.md` for the owner to rule on.
- Before writing about a canon thing, look it up (`/canon <name>`). Never write canon facts from memory.
- **If you are unsure whether something contradicts canon, stop and ask.**

**Owner's ruling, 2026-11-13: the world must be expansive and huge.** New places may be added even where they shift canon lore slightly (a new village on a road canon calls empty, a new quarter in a canon city, a new island on a canon sea). For new places, growth wins over strict agreement with canon:
- Do not stop and ask for a slight shift caused by a new place. Add it, and log the shift in `docs/lore/conflicts.md` so the owner can see what moved.
- A slight shift bends a detail. It does not remove, rename or move a canon place, or change who rules it.
- This covers places only. The rules above still hold for canon people, groups and histories, and `canon/` is still never edited.
- Stop and ask only when a change is large: it would undo a canon place, person or story.

## World rules (fixed)

- **The world is static.** Realms, rulers and borders never change. Players rise within the world's order, never overturn it. No quest breaks the world.
- **Some mysteries stay unresolved forever,** such as the Lease, the Ring and the Hum's origin. The game hints and never answers.
- **No real-world historical terms in game text.** Real cultures inspire places, but the words on screen are Allora's own. Plant, animal and food names are fine.
- **Romance is between adults only.**
- **The player can never learn witch magic.** Countermagic is the closest a player comes.
- **Augury and divination give no hints about the future of play,** except where a faith says otherwise (Nim's dreams).
- **Less text in the interface.** Explanations live in the codex, and the screens stay clean.
- **No level-up cards or interrupting pop-ups.** Progress is shown quietly in place.
- **Lives do not age, and nothing is inherited.** New lives come only from the Tapestry.

## Design habits

- **Features are rare.** Most schools, faiths and professions lack most features, so each feels different.
- **Every number has a source in the world** (a teacher, a tool, a Weather, a god).
- **One simulation for everything.** Hired people run the same activities the player does.
- **Lore first.** A new place starts with who lives there and why.

## Architecture

TypeScript monorepo (pnpm). The engine runs in a Web Worker and owns all game state and rules. The UI (React for screens, PixiJS for the map and scenes) only displays state and sends orders. **No game logic in the UI.** All world content is YAML in `content/`, validated by zod schemas. Saves live in IndexedDB with versioned migrations.

## Commands

- `pnpm dev`: run the game locally
- `pnpm test`: unit tests (Vitest)
- `pnpm lint:content`: schemas, references, canon lint, lore lint
- `pnpm balance`: the balance bot
- `pnpm extract`: re-run the canon extractors

(Create these scripts in Phase 0 if they do not exist yet.)

## House style for game text

Short, concrete, in-world. No interface jargon in the world's words, no emoji in game text, no explaining in UI text (the codex explains).

## How to work

- One GitHub issue, one branch, one pull request.
- Each PR says what changed, what you could not decide, and includes new lines from `docs/lore/additions.md` and the balance report when relevant.
- Small modules, under about 400 lines.
- Content in batches of about 20 entries, linted, then reviewed.
- Keep `docs/phase-N.md` current: tick done items and record decisions, so a fresh session can pick up where the last one stopped.
